# The Postman Framework

The Postman Framework is a set of rules that defines how should endpoints, envvars, scripts and documentation integrate together to build a seamless testing experience

## 1. Endpoints

The main goal is to reduce the amount of manual work required to execute and test the endpoints under different circumnstances.  For that  purpose we use environment variables and pre & post request scripts to keep the state of the flow automated.

## 2. Environment Variables

- MANUAL_ENVVARS: Variables that cannot by any case be calculated or pre generated, ex. Urls, api keys, etc... They are written in UPPER_SNAKE_CASE
- $flow_envvars: Variables that are generated by part of the flow, ex. /auth/login will generate an $access_token, /auth/signup will generate also a $user_id.  This will prevent the copypaste between requests, anyway we need to be careful to not create flow envvars that we dont use in the future. They are written with a starting "$"
- _autogenerated_envvars: Mocked values that are generated before the request, this is done mostly when dynamic values are required. Ex. Dates, phone numbers on registration, passwords, etc... Most values dont need to be autogenerated and can and should be hardcoded, we reserve the _autogenerated_envvars to that special dynamic cases.  They are written by a starting "_"

## 3. Post request scripts (Tests)

They dont actually need to be "tests", reserve this space to setup any $flow_envvar if necessary

## 4. Pre-request scripts

Reserved for generating required _autogenerated_envvars
